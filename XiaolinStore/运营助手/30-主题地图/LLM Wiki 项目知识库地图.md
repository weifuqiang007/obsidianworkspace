# LLM Wiki 项目知识库地图

## 中心问题

如何让分散在文章、对话、代码研究和随手记中的内容，按项目持续沉淀为可追溯、可复用、可增量维护的知识网络？

## 核心结构

- [[Raw-Wiki-Schema 三层知识架构]]：系统骨架。
- [[LLM Wiki]]：增量维护的结构化知识层。
- [[Obsidian]]：存储、连接与呈现。
- [[Codex]]：执行与编排。
- [[WeSight]]：Obsidian 内的可视化集成入口。

## 项目化路由

先根据 [[99-系统/项目分类与知识路由|项目分类与知识路由]] 判断内容属于哪个项目；跨项目知识只保存一份 Raw，通过双链共享。

## 增量闭环

```text
高价值资料进入项目 Raw
→ 检索已有 Wiki
→ 创建来源摘要
→ 更新概念、实体、方法或洞察
→ 更新主题地图与索引
→ 追加整理日志
→ 查询时从 Wiki 回溯 Raw
```

## 人机分工

| 人 | Agent |
|---|---|
| 选择高价值资料 | 读取和分类 |
| 设定项目边界和规则 | 查重与增量更新 |
| 判断敏感或冲突结论 | 建双链、索引和日志 |
| 批准删除、迁移和发布 | 执行可回滚的结构化维护 |

## 下一步

1. 从每个项目选择 1—3 个高价值 Codex 对话作为 Raw。
2. 对现有“情感陪伴项目”跑一次增量维护，补来源摘要和实体页。
3. 给“反身性研究核心代码”建立代码架构、RAG、权限和产品主题地图。
4. 每周巡检空主题、孤立页面、待核实问题和长期未更新页面。
