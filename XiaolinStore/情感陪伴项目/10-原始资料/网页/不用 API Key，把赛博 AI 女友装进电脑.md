# 不用 API Key，把赛博 AI 女友装进电脑

## 原文主题

这篇文章是一篇本地语音 Agent 部署教程。它用“赛博 AI 女友”作为包装，实际讲的是如何在有 NVIDIA 显卡的电脑上，用 VAD、Whisper、本地 LLM 和 Qwen3-TTS 搭建一个能听、能识别、能回复、能用指定音色说话的本地语音交互系统。

## 核心链路

```text
用户开口说话
→ VAD 判断是否说完
→ Whisper 将语音转为文字
→ 本地 LLM 生成回复
→ Qwen3-TTS 将回复合成为指定音色
→ 播放语音
```

## 文章要点

1. 目标不是安装一个聊天软件，而是跑通一条完整语音链路。
2. “女友感”主要由两部分组成：参考音频决定音色，system prompt 决定说话方式。
3. 首要目标是完成四项验证：能听、能识别、能回复、能出声。
4. 部署顺序应当分层验证：先选模型组合，再建环境、下载模型、验证本地 LLM，最后接入麦克风和 TTS。
5. 显存是关键限制因素。文章建议 8GB 显存从 7B Q4 和较小 TTS 模型开始，12GB 可以跑基础组合，16GB 更适合 14B Q4。
6. 声音参考音频应当干净、短、单人声、无背景音乐、无明显噪声。
7. 声音克隆必须使用自己录制、公开授权或获得本人明确同意的音频。
8. 本地运行阶段可以不依赖云端 LLM API，但下载模型和依赖阶段仍需要联网。
9. 端口应绑定在 `127.0.0.1`，不要把本地服务暴露到公网。

## 对项目的直接启发

- 可以把虚拟人情感陪伴项目的第一阶段目标设为“语音闭环跑通”，而不是先追求完整人设、长期记忆和复杂形象。
- 语音陪伴的最小可用闭环可以拆成：语音输入、语音识别、情绪或意图理解、LLM 回复、TTS 输出。
- 本地部署可以作为隐私卖点，但普通用户的安装门槛较高，适合作为原型验证或高隐私版本，不一定适合作为首个大众版本。

## 局限

- 原文偏技术部署教程，不是完整的情感陪伴产品设计方案。
- 没有展开长期记忆、人格一致性、关系边界、心理安全、未成年人保护等问题。
- 没有涉及虚拟人视觉表现，例如 Live2D、3D Avatar、表情、动作和嘴型同步。
- “赛博 AI 女友”的叙事容易把陪伴产品窄化为恋爱角色，需要在产品定位上谨慎处理。
