# 一次知识库请求的完整调用链

以列表接口为例：

```http
GET /rag/kb/list
Authorization: Bearer <token>
```

## 总调用链

```text
HTTP 请求
→ 全局 ASGI 中间件
→ FastAPI 匹配 /rag/kb/list
→ PreAuthDependency 验证 token，写入 RequestContext
→ RoleInterfaceAuthDependency 检查 admin/teacher/student
→ ViewerDependency 从注册表取 Policy
→ LearningKbScopePolicy.build_principal()
→ 构造 LearningKbPrincipal
→ Controller.get_list()
→ Service.get_list()
→ LearningKbScopePolicy.visible_filter()
→ DAO 执行带权限条件的 SQL
→ 响应经中间件返回
```

## 1. 全局中间件

`middlewares/handle.py` 注册了上下文清理、CORS、GZip、响应头、Trace、DemoMode 和传输加密。

它们包在 FastAPI 路由外面。其中 `ContextCleanupMiddleware` 会在请求处理完成后执行：

```python
RequestContext.clear_all()
```

## 2. 路由级依赖不是中间件

知识库 Router 定义：

```python
knowledge_base_controller = APIRouterPro(
    prefix='/rag/kb',
    dependencies=[
        PreAuthDependency(),
        RoleInterfaceAuthDependency(
            ['admin', 'teacher', 'student'],
        ),
    ],
)
```

FastAPI 在调用 endpoint 之前解析这些 `Depends`。

## 3. `PreAuthDependency`

`PreAuth.__call__()` 读取：

```python
token = request.headers.get('Authorization')
```

然后调用：

```python
current_user = await LoginService.get_current_user(
    request, token, db,
)
```

`LoginService.get_current_user()` 在验证用户后写入：

```python
RequestContext.set_current_user(current_user)
```

`RequestContext` 内部使用 `ContextVar`，使当前用户信息按异步请求隔离。

## 4. `RoleInterfaceAuthDependency`

它从 `RequestContext` 取出用户：

```python
current_user = RequestContext.get_current_user()
```

然后检查 `role_key` 是否包含 `admin` / `teacher` / `student` 中的至少一个。

## 5. `ViewerDependency`

控制器参数：

```python
principal: KbPrincipal = ViewerDependency(
    'rag.knowledge_base'
)
```

`ViewerDependency` 返回 `Depends(_resolve)`：

```python
async def _resolve(request: Request, query_db: AsyncSession):
    current_user = RequestContext.get_current_user()
    policy = ScopeRegistry.get('rag.knowledge_base')
    return await policy.build_principal(
        query_db,
        current_user,
    )
```

注册表中当前保存的是 `LearningKbScopePolicy`，所以实际调用：

```python
await LearningKbScopePolicy.build_principal(...)
```

## 6. 构造教育主体

`build_principal()` 先读取 `user_id`、`role_keys`、`is_admin` 和主角色。

### 学生

查询学生档案和班级，构造：

```python
LearningKbPrincipal(
    user_id=100,
    is_admin=False,
    role='student',
    role_keys=['student'],
    school_id=10,
    class_id=25,
)
```

### 教师

查询所属学校、任课班级、所带学生和学校部门范围，构造：

```python
LearningKbPrincipal(
    user_id=200,
    is_admin=False,
    role='teacher',
    role_keys=['teacher'],
    school_id=10,
    taught_class_ids=[25, 26],
    owned_student_ids=[100, 101, 102],
    school_dept_ids=[10, 20, 25, 26],
)
```

## 7. Controller 和 Service

Principal 解析完成后，FastAPI 才调用：

```python
async def get_list(query_db, principal):
    kb_list = await KnowledgeBaseService.get_list(
        query_db,
        principal,
    )
```

Service 再从注册表取出当前 Policy：

```python
cond = _policy().visible_filter(
    principal,
    RagKnowledgeBase,
)
return await KnowledgeBaseDao.get_visible_list(db, cond)
```

## 8. 权限条件

`LearningKbScopePolicy.visible_filter()` 把业务规则翻译成 SQLAlchemy 条件。

| 主体 | 可见范围 |
|---|---|
| 管理员 | 全部 |
| 学生 | 公共 + 本校 + 本班 + 本人个人库 |
| 教师 | 公共 + 本校 + 学校范围内班级 + 所带学生个人库 |

该条件交给 DAO，由数据库过滤，而不是先查全部数据再在 Python 中过滤。

## 其他端点使用 Policy 的方式

| 端点 | Policy 方法 | 用途 |
|---|---|---|
| 创建 | `validate_create()` | 检查当前角色能否创建指定 scope |
| 列表 | `visible_filter()` | 生成 SQL where 条件 |
| 详情/检索 | `can_access()` | 对单个知识库进行 Python 权限判定 |
| 更新/删除 | Service 直接检查 owner/admin | 仅 owner 或 admin 可改删 |
